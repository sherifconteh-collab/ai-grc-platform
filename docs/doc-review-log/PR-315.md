# Documentation review — PR #315

A Claude Code session with direct repo access performed this review live. The cue was the independent code review of this PR. The PR wires the Qualys and ITSM (ServiceNow) connectors into **Run** on the Integrations Hub, replacing simulated runs, so their outbound calls became reachable from tenant-entered URLs. That review found no private-network guard on them, and the fix is in this PR.

## Fixed

- **`docs/FEDRAMP_DEPLOYMENT_GUIDE.md` §8, "Integration with Your ITSM Platform"**
  - It did not say which hosts the connectors may reach. It now does: public `https` only, and a name resolving to a private address is refused. `CONNECTOR_ALLOW_PRIVATE_HOSTS=true` is the self-hosted opt-in.
  - It now also says a failed call or an unexpected response is a failed run, not zero findings.
  - Checked against `utils/netGuard.assertSafeUrl` and against `serviceNowService` / `qualysService`, which now reject a reply without `result` / `HOST_LIST_VM_DETECTION_OUTPUT`.
- **`backend/.env.example`**: documents `CONNECTOR_ALLOW_PRIVATE_HOSTS`, next to the other outbound settings.

## Already accurate

- **`README.md` lines 499–500, 506, 940 and 1006** describe the Qualys and ITSM connectors by capability only. The guard doesn't change any of those claims.
- **§9 "Weekly Vulnerability Scans"** (configure `qualys_vmdr`, then sync) still matches the route: `integrationsHub.js` `CONNECTOR_SYNC_HANDLERS`.

## Noted, out of scope

- **DNS rebinding.** Closed in round 2 (below).
- **§9, step 2 ("Set the sync schedule to `daily`")**: the connector schedule is stored, but whether a scheduler job actually runs these connectors was not verified in this review.

## Round 2: remaining audit findings

This round brings in the fixes made in ControlWeaver-Pro that apply to this codebase.

- **Code changes:**
  - Connections are pinned: `guardedLookup` on the ITSM and Qualys requests, and `safeFetch` for Splunk, organization Ollama URLs (including the connection test in `routes/orgSettings.js`) and webhook delivery.
    - Splunk and the Ollama URL previously had no private-network check at all.
    - Webhook delivery checked only the literal hostname and followed redirects.
  - The web app's refresh token is now an HttpOnly cookie (`utils/refreshCookie.js`). This covers `auth.js`, `sso.js` and `passkeys.js` on the server, and `lib/api.ts`, `tokenStore.ts` and `AuthContext` in the frontend.
  - Passkey sign-in now refuses deactivated users.
- **Docs fixed or added:**
  - `README.md`: the refresh-token rotation line now says the browser keeps the token in an HttpOnly cookie.
  - `docs/FEDRAMP_DEPLOYMENT_GUIDE.md` §8: the host rule now covers Splunk, Ollama and webhooks, and says each address is checked at connect time.
  - `backend/.env.example`: documents `REFRESH_COOKIE_SAMESITE`, `WEBHOOK_ALLOW_PRIVATE_HOSTS` and `WEBHOOK_ALLOW_HTTP`.
- **Already accurate:** the README's other authentication claims (HS384 JWTs, rotation, session cap). The token lifetimes did not change.
- **Out of scope item from round 1 is now closed:** DNS rebinding.
